# 行为速度规划模块详解

在 `behavior_planning.launch.xml` 文件中，通过 `behavior_velocity_planner_launch_modules` 参数配置了 **行为速度规划器（Behavior Velocity Planner）** 的场景插件模块。每个模块负责处理特定交通场景下的速度规划决策。以下是各模块的详细功能说明：

---

## 1. CrosswalkModulePlugin（人行横道模块）

| 项目 | 说明 |
|------|------|
| **功能** | 检测车辆前方的人行横道，判断是否有行人正在通过或即将通过 |
| **输入** | 行人检测数据、高精地图人行横道信息 |
| **输出** | 减速或停车指令 |
| **典型场景** | 车辆接近斑马线时，若有行人则停车让行 |

**工作原理**：
- 从地图中获取人行横道位置
- 结合感知系统检测的行人位置
- 预测行人轨迹，判断是否与车辆路径冲突
- 生成相应的速度限制或停止点

---

## 2. WalkwayModulePlugin（步行道模块）

| 项目 | 说明 |
|------|------|
| **功能** | 处理步行道区域的速度规划，确保行人安全 |
| **输入** | 步行道地图信息、行人检测数据 |
| **输出** | 速度限制指令 |
| **典型场景** | 车辆经过商业区步行道、共享道路区域 |

**工作原理**：
- 识别地图中的步行道区域
- 检测步行道上的行人或障碍物
- 根据行人密度调整车速

---

## 3. TrafficLightModulePlugin（交通信号灯模块）

| 项目 | 说明 |
|------|------|
| **功能** | 根据交通信号灯状态进行停车或通过决策 |
| **输入** | 信号灯识别结果、信号灯位置地图信息 |
| **输出** | 停车点或通行速度指令 |
| **典型场景** | 红绿灯路口停车等待或通行 |

**工作原理**：
- 获取当前车道对应的信号灯组
- 解析信号灯颜色（红/黄/绿/未知）
- 计算停车线位置，生成平滑的减速轨迹
- 处理信号灯状态转换时的过渡逻辑

---

## 4. IntersectionModulePlugin（交叉路口模块）

| 项目 | 说明 |
|------|------|
| **功能** | 处理无信号灯交叉路口的通行优先级判断 |
| **输入** | 交叉路口地图信息、其他车辆检测数据 |
| **输出** | 停车让行或通行指令 |
| **典型场景** | 无信号灯路口、让行标志路口 |

**工作原理**：
- 识别交叉路口类型（优先/让行/环岛等）
- 检测交叉方向来车
- 根据交通规则判断通行优先级
- 必要时生成临时停止点

---

## 5. MergeFromPrivateModulePlugin（私有道路汇入模块）

| 项目 | 说明 |
|------|------|
| **功能** | 处理从私有道路（停车场、小区等）汇入主路的场景 |
| **输入** | 汇入点地图信息、主路交通流数据 |
| **输出** | 停车等待或汇入速度指令 |
| **典型场景** | 从停车场出口汇入主干道 |

**工作原理**：
- 识别私有道路与主路的汇合点
- 检测主路来车速度和距离
- 计算安全汇入时机
- 生成等待或加速汇入的速度曲线

---

## 6. BlindSpotModulePlugin（盲区模块）

| 项目 | 说明 |
|------|------|
| **功能** | 检测车辆传感器盲区内的潜在危险 |
| **输入** | 盲区地图定义、感知数据覆盖范围 |
| **输出** | 减速或停车指令 |
| **典型场景** | 建筑物遮挡、弯道盲区 |

**工作原理**：
- 根据地图定义传感器盲区范围
- 评估盲区内可能出现障碍物的风险
- 在高风险区域提前减速
- 结合历史感知数据判断风险等级

---

## 7. DetectionAreaModulePlugin（检测区域模块）

| 项目 | 说明 |
|------|------|
| **功能** | 在特定区域加强障碍物检测，触发速度调整 |
| **输入** | 检测区域地图定义、障碍物检测数据 |
| **输出** | 速度限制或停车指令 |
| **典型场景** | 学校区域、施工区域、事故高发区 |

**工作原理**：
- 从地图读取检测区域定义
- 在该区域内提高障碍物检测敏感度
- 检测到障碍物时触发减速或停车

---

## 8. VirtualTrafficLightModulePlugin（虚拟交通灯模块）

| 项目 | 说明 |
|------|------|
| **功能** | 处理云端或基础设施下发的虚拟信号灯指令 |
| **输入** | 虚拟信号灯状态消息 |
| **输出** | 停车或通行指令 |
| **典型场景** | 车路协同（V2X）场景、远程交通管制 |

**工作原理**：
- 接收 `virtual_traffic_light_states` 话题消息
- 解析虚拟信号灯状态
- 与物理信号灯逻辑类似，但信号源来自云端/路侧

---

## 9. NoStoppingAreaModulePlugin（禁止停车区域模块）

| 项目 | 说明 |
|------|------|
| **功能** | 确保车辆不在禁止停车区域内停车 |
| **输入** | 禁止停车区域地图信息、当前停车计划 |
| **输出** | 调整停车点位置 |
| **典型场景** | 避免在路口、人行横道上停车 |

**工作原理**：
- 识别地图中的禁止停车区域
- 检查计划的停车点是否落在禁停区内
- 若在禁停区内，将停车点前移或后移到安全位置

---

## 10. StopLineModulePlugin（停止线模块）

| 项目 | 说明 |
|------|------|
| **功能** | 处理地图中定义的停止线，确保车辆在停止线前停车 |
| **输入** | 停止线地图信息、停车触发条件 |
| **输出** | 停止点位置 |
| **典型场景** | 路口停止线、收费站、检查站 |

**工作原理**：
- 从地图获取前方停止线位置
- 当需要停车时（如红灯、让行），将停止点设置在停止线前
- 计算平滑减速轨迹

---

## 11. OcclusionSpotModulePlugin（遮挡点模块）

| 项目 | 说明 |
|------|------|
| **功能** | 检测因遮挡导致的感知盲区风险点 |
| **输入** | 点云数据、地图遮挡区域定义 |
| **输出** | 减速指令 |
| **典型场景** | 路边停车遮挡、建筑物角落 |

**工作原理**：
- 分析点云数据识别遮挡区域
- 预测遮挡后可能出现的障碍物
- 在接近遮挡点时提前减速
- 与 [BlindSpotModulePlugin](file:///home/developer/autoware/autoware_devel/src/universe/autoware_universe/planning/behavior_velocity_planner/autoware_behavior_velocity_blind_spot_module/include/autoware/behavior_velocity_blind_spot_module/manager.hpp#L59-L61) 类似，但更侧重于动态遮挡

---

## 12. RunOutModulePlugin（突然冲出模块）

| 项目 | 说明 |
|------|------|
| **功能** | 预防行人或车辆从路边突然冲出的风险 |
| **输入** | 路边障碍物检测、点云数据 |
| **输出** | 预防性减速指令 |
| **典型场景** | 路边停车间隙、巷口、小区出口 |

**工作原理**：
- 检测路边可能隐藏行人的区域
- 评估突然冲出的风险等级
- 在高风险区域提前降低车速
- 通常与 `compare_map_filtered_pointcloud` 配合使用

---

## 13. SpeedBumpModulePlugin（减速带模块）

| 项目 | 说明 |
|------|------|
| **功能** | 检测前方减速带，提前减速通过 |
| **输入** | 减速带地图位置信息 |
| **输出** | 通过减速带的目标速度 |
| **典型场景** | 小区入口、停车场、学校区域减速带 |

**工作原理**：
- 从地图获取减速带位置
- 计算到达减速带前的减速轨迹
- 确保以安全速度通过减速带
- 通过后恢复正常速度

---

## 14. NoDrivableLaneModulePlugin（无可行驶车道模块）

| 项目 | 说明 |
|------|------|
| **功能** | 检测前方无可行驶车道的情况，触发停车 |
| **输入** | 车道通行状态、地图车道信息 |
| **输出** | 停车指令 |
| **典型场景** | 道路封闭、车道施工、交通管制 |

**工作原理**：
- 检查当前车道的可通行状态
- 若前方车道不可行驶，提前规划停车
- 避免车辆驶入封闭或危险区域

# 模块启用控制

在 launch 文件中，每个模块都可以通过对应的 `launch_*_module` 参数独立启用或禁用：

```xml
<arg name="launch_crosswalk_module" default="true"/>
<arg name="launch_traffic_light_module" default="true"/>
<!-- ... 其他模块 -->
```

这种设计允许：
- **灵活配置**：根据实际场景选择需要的模块
- **性能优化**：禁用不需要的模块减少计算开销
- **测试调试**：单独启用特定模块进行测试

# 与 node.cpp 的关联

在 `node.cpp` 中，这些模块通过以下方式加载：

```cpp
// 构造函数中读取 launch_modules 参数
for (const auto & name : declare_parameter<std::vector<std::string>>("launch_modules")) {
    if (name == "") {
        break;
    }
    planner_manager_.launchScenePlugin(*this, name);
}
```

每个模块插件在运行时：
1. 订阅所需的感知数据
2. 评估当前场景是否触发
3. 若触发则生成速度修改建议
4. [planner_manager_](file:///home/developer/autoware/autoware_devel/src/core/autoware_core/planning/behavior_velocity_planner/autoware_behavior_velocity_planner/include/autoware/behavior_velocity_planner/node.hpp#L120-L120) 综合所有模块建议，生成最终速度规划路径
