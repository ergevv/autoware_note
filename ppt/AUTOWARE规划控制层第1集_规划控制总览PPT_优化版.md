# 一个最简单的任务

```text
车辆当前在 A 点
目标位姿在 B 点
```

问题：

```text
车辆应该怎么开过去？
```

<!--

# 目标点不能直接控制车辆

目标点没有告诉车辆：

1. 应该经过哪些车道
2. 在车道内具体走哪条线
3. 每一段应该开多快
4. 当前方向盘应该转多少
5. 当前应该加速还是减速

<!--
讲解备注：
目标点只是任务意图，不是可执行命令。车辆不能从当前位置直接“朝目标点打方向”，因为中间可能有不可通行区域、逆向车道或超出车辆转弯能力的路径。
这页是引出分层规划控制的关键。

配图建议：
左侧放目标点图标，右侧放五个空白问题卡片。
可以用红色叉号标注“Goal != Control Command”。

# 本质是逐层翻译

```text
我要去哪里
  -> 应该经过哪些车道
  -> 在车道里走哪条线
  -> 每个位置以多快速度通过
  -> 当前车辆怎么执行
```

抽象目标越往后，越接近底盘可执行命令。

<!--

# 四个核心概念

| 名称 | 回答的问题 | 典型结果 |
|---|---|---|
| Route | 经过哪些车道 | lanelet 序列、route sections |
| Path | 在车道里走哪条线 | 几何路径点 |
| Trajectory | 每个点以多快速度通过 | 带速度轨迹点 |
| Control | 当前怎么操作车辆 | 转向、加速度、制动 |

<!--
讲解备注：

配图建议：

Route 是高亮车道序列，Path 是车道内一条线，Trajectory 是带速度颜色的点列，Control 是方向盘/踏板命令。
-->

# Route：车道级路线

Route 回答：

```text
从当前位置到目标点，应该经过哪些车道？
```

输入通常包括：

- 当前车辆位姿
- 目标位姿
- Lanelet 地图
- 途经点或任务约束

<!--
讲解备注：
Route 不是控制器要跟踪的曲线。它更像车道级导航结果。
它解决的是“拓扑上怎么走”，不是“车辆此刻怎么打方向”。

配图建议：
画一个 Lanelet 道路图，把主路线经过的车道高亮。
每个 lanelet 用小矩形或多边形表示，并用箭头标出行驶方向。
-->

---

# Path：车道内的几何走线

Path 回答：

```text
在 Route 给定的道路空间里，
车辆具体沿哪条几何线行驶？
```

它需要考虑：

- 车道边界
- 障碍物
- 路径平滑性
- 车辆能否跟踪

<!--
讲解备注：
同一条 route 里可以有很多 path。比如走车道中心线、绕开障碍物、换道、靠边停车，都会产生不同 path。
Route 是道路走廊，Path 是走廊里的具体线。

配图建议：
同一个高亮车道内画三条不同的 path：中心线、避障偏移线、靠边线。
用同色车道背景说明它们属于同一条 route。
-->

---

# Trajectory：带速度的路径

Trajectory 可以理解为：

```text
Path + Velocity
```

轨迹点常包含：

```text
x, y, yaw, velocity, acceleration
```

同一条几何路径，不同速度曲线会产生完全不同的驾驶行为。

<!--
讲解备注：
强调 trajectory 比 path 多了速度和时间含义。
同一条线，如果一个版本高速通过，一个版本停车等待，行为完全不同。

配图建议：
同一条路径上用颜色表示速度，绿色表示快，黄色表示慢，红色表示停车。
下方可以画 v-s 曲线，显示速度沿路径变化。
-->

---

# Control Command：当前执行命令

Control Command 回答：

```text
车辆此刻应该怎么执行？
```

常见输出：

- 转向角或转向角速度
- 目标加速度
- 制动命令
- 档位命令

<!--
讲解备注：
控制器不重新决定路线。它根据当前车辆状态和目标轨迹之间的误差，输出当前时刻的控制命令。
这也是规划和控制的边界：规划给未来目标，控制给当前动作。

配图建议：
左侧放 trajectory，右侧放控制命令卡片：
steering、acceleration、brake、gear。
中间放 Controller 模块。
-->

# Mission Planner 做什么

```text
目标点 + 当前位姿 + Lanelet 地图
        ->
车道级 Route
```

核心步骤：

1. 找起点所在车道
2. 找目标所在车道
3. 在车道图上搜索
4. 输出 route sections

<!--
讲解备注：
强调 Mission Planner 不是避障模块，也不是轨迹跟踪模块。它做的是车道级路线规划。
可以提示下一集会详细讲 Lanelet、起终点匹配、route sections。

配图建议：
左侧输入三张卡片：当前位姿、目标位姿、Lanelet 地图。
右侧输出一串高亮 lanelet 或 route sections。
-->

---

# Lanelet 地图为什么重要

Lanelet 地图提供：

- 车道边界
- 中心线
- 行驶方向
- 车道连接关系
- 可换道关系
- 交通规则属性

没有拓扑关系，系统就不知道哪些车道能连起来。

<!--
讲解备注：
Lanelet 不是普通图片地图，它包含拓扑和规则。
Mission Planner 能在车道图上搜索，依赖的就是这些连接关系和规则属性。

配图建议：
画一个 lanelet：左边界、右边界、中心线、方向箭头，再画多个 lanelet 之间的连接。
旁边加一个小图例说明 boundary、centerline、successor、adjacent。
-->

---

# Behavior / Start Planner 做什么

它回答更局部的行为问题：

- 是否需要换道
- 是否需要停车
- 是否需要靠边
- 是否需要从路边起步
- 是否需要从自由空间回到车道

Mission Planner 给方向，行为规划决定具体场景动作。

<!--
讲解备注：
可以举“车停在路边”的例子：route 在路上，但车辆当前位置可能不在 lanelet 中心线上，需要 pull out。
Behavior / Start Planner 处理的是局部场景行为，不是全局路线。

配图建议：
画四个小场景：换道、停车、靠边、路边起步。
用同一条 route 背景说明这些都是 route 之上的局部行为。
-->

# Hybrid A* 解决什么

普通图搜索常把状态看成：

```text
(x, y)
```

车辆局部规划常需要：

```text
(x, y, yaw, gear)
```

因为车辆有朝向、最小转弯半径，还可能需要前进和倒车。

<!--
讲解备注：
这一页只是预告，不展开代价函数。告诉观众：Hybrid A* 用车辆可执行的运动原语做搜索。
重点是状态里必须包含 yaw 和 gear，否则无法表达车辆真实可达性。

配图建议：
画一个停车位或路边起步场景。
左边用普通网格搜索直线连接，右边用车辆转弯圆弧和倒车动作连接。
-->

# 路径为什么需要平滑

上游路径可能来自：

- 车道中心线
- 路径拼接
- 避障绕行
- 离散采样
- 历史轨迹复用

轻微折角会放大成曲率抖动和转向抖动。

<!--
讲解备注：
路径看起来只是轻微不平滑，但控制器会放大这种几何抖动。
曲率抖动会影响速度规划，也会影响横向控制的转角命令。

配图建议：
左边画锯齿路径，右边画平滑路径。
下方加一个小曲率曲线对比：锯齿路径曲率有尖峰，平滑路径曲率更连续。
-->

# Elastic Band 的位置

```text
原始离散路径
      ->
横向微调路径点
      ->
更光顺的路径
```

直觉：

```text
让路径像一根橡皮筋一样变平滑，
但不能随意偏离原路径。
```

<!--
讲解备注：
这里可以先给直觉：每个路径点只能沿法向移动一小段，目标是减少折角。
不要提前讲完整 QP，只让观众知道它是几何路径平滑的一环。

配图建议：
画一串离散点，每个点有一条短法向移动线段。
再画一根被拉平的橡皮筋，但要保留道路边界限制。
-->

# MPT 轨迹优化的位置

MPT 更关注：

- 局部参考线
- 车辆模型
- 道路边界
- 软约束
- 轨迹连续性
- warm start

它让轨迹更适合后续控制器跟踪。

<!--
讲解备注：
不要把 MPT 和 MPC 混在一起。MPT 偏轨迹优化，MPC 偏控制输入优化。后面会专门讲。
MPT 的位置在控制器之前，它输出更好的轨迹，不是直接输出底盘命令。

配图建议：

# Velocity Smoother 做什么

```text
几何轨迹
  + 速度上限
  + 当前车速/加速度
  + 运动约束
      ->
满足速度、加速度、jerk 的轨迹
```

路径回答“走哪里”，速度平滑回答“怎么快慢变化”。

<!--
讲解备注：
这里把几何和速度分开。路径几何再好，如果速度曲线突然跳变，车辆仍然开不舒服。
Velocity Smoother 是把轨迹变得更可执行、更舒适的重要模块。

配图建议：
在路径下面画速度曲线 v(s)，停车点前速度逐渐降到 0。
可以用三条曲线对比：速度、加速度、jerk。
-->

---

# 速度不能硬裁剪

错误直觉：

```text
v = min(v, speed_limit)
```

真实车辆还要满足：

$$
0 \le v \le v_{\max}
$$

$$
a_{\min} \le a \le a_{\max}
$$

$$
j_{\min} \le j \le j_{\max}
$$

<!--
讲解备注：
解释：限速突然降低时，车辆不能瞬间降速；停车点前要提前减速；jerk 影响乘坐舒适性。
这一页为第 5 集做铺垫。

配图建议：
画一条被硬裁剪的速度曲线，速度突然下降；旁边画一条平滑减速曲线。
再用红色标注硬裁剪会导致加速度或 jerk 尖峰。
-->

# Controller 做什么

```text
当前车辆状态 + 目标轨迹
        ->
当前控制命令
```

横向控制关注：

- 横向误差
- 航向误差
- 曲率或转角

纵向控制关注：

- 速度误差
- 加速度
- 制动

<!--
讲解备注：
控制器是链路最后一层，但它不是万能的。上游轨迹质量很差时，控制器也很难稳定跟踪。
这里可以强调：控制器跟踪目标，不负责重新做路线规划。

配图建议：
左侧画当前车辆偏离目标轨迹，标注横向误差和航向误差。
右侧画控制输出：steering、acceleration、brake。
-->

# Pure Pursuit：几何控制

核心想法：

```text
不要追最近点，
而是追轨迹前方的前瞻点。
```

在车辆坐标系下：

$$
\kappa = \frac{2y}{x^2+y^2}
$$

再由自行车模型转换成转角。

<!--
讲解备注：
这里只建立直觉，不展开完整推导。后面 Pure Pursuit 单集会推。
告诉观众 Pure Pursuit 是“几何直觉很强”的横向控制方法。

配图建议：
画车辆、前瞻圆、前瞻点、连接圆弧。
标出车辆坐标系下前瞻点坐标 (x, y)，并用小公式卡片写 κ。
-->

# MPC：优化控制

MPC 的核心想法：

```text
预测未来一段车辆运动，
选择一串控制输入，
让未来误差尽量小，
同时满足转角和变化率约束。
```

典型结果：

```text
U* = [u0, u1, ..., uN-1]
```

实际只执行第一个控制量。

<!--
讲解备注：
解释“只执行第一个”是 MPC 的闭环思想。下一帧根据新状态重新求解。
第一集不推 QP，只让观众记住：MPC = 模型预测 + 优化 + 约束。

配图建议：
画一辆车前方展开多步预测轨迹，时间轴上有 u0、u1、u2。
高亮 u0，旁边写“只执行第一步”。
-->

# 车辆模型为什么重要

车辆不是点，也不能横着平移。

常用自行车模型：

$$
\dot{x}=v\cos\psi
$$

$$
\dot{y}=v\sin\psi
$$

$$
\dot{\psi}=\frac{v}{L}\tan\delta
$$

Hybrid A*、Pure Pursuit、MPC 都会用到这个直觉。

<!--
讲解备注：
第一集只讲物理含义：速度和朝向决定位置变化，转角通过轴距影响航向变化。
不用展开 Frenet 或线性化，把它留给后续控制课程。

配图建议：
画自行车模型或单轨车辆模型。
标注速度 v、航向 ψ、轴距 L、前轮转角 δ，以及航向变化箭头。
-->

# 为什么优化问题反复出现

很多模块都在做：

```text
最小化某个代价
同时满足一些约束
```

例子：

- 路径尽量平滑，但不能偏离太多
- 速度尽量高，但 jerk 不能太大
- 控制误差尽量小，但转角不能超限
- 轨迹尽量贴近参考，但不能越界
